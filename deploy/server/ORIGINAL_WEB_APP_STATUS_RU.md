На всех семи поинтах упрощённая страница заменена сборкой исходного `src/App.tsx` проекта. Исходники опубликованы с явного разрешения владельца в `web-app/` ветки `codex/wan-prepare-20261118`, commit `3df8173`. Чаты, звонки, разделы и модульные компоненты включены в сборку исходного приложения; упрощённый `src/point-web/main.ts` больше не является главной страницей.

## Фактическая граница

Это исправление раздаваемого интерфейса, а не завершение подключения мессенджера к mesh. Его Django/JWT API, общие данные приложения между точками входа, авторизация прикладных сессий и WebSocket/звонки ещё не развёрнуты как работающая mesh-служба. У исходного settings.py режим `mesh` явно запрещён как нереализованный. Этот запрет не удалён и не обойдён запуском семи разрозненных personal-серверов.

Поэтому `/api/*` явно отвечает JSON/503 `application_api_not_connected`, `/ws/*` — 503. Парольные запросы исходного приложения не отправляются в другой mesh-login API, и HTML не выдаётся за ответ приложения. Пользователь ещё не может войти в мессенджер и переписываться. Успешные старые проверки mesh login/session/logout НЕ подтверждают работу входа в исходный мессенджер.

## Следующая необходимая работа

1. Подключить прикладную авторизацию исходного UI к сетевой учётной записи и определить устойчивое общее хранение профилей/контактов/членства, чтобы переход на другой поинт сохранял тот же аккаунт.
2. Развернуть настоящий прикладной API с существующим cipher transport и проверяемыми mesh-сессиями; проверить отправку и чтение сообщений между разными входами, включая перезапуск.
3. Подключить публичный WebSocket/signaling и TURN для звонков, затем загрузку/выдачу модулей и медиа; проверить двумя настоящими сеансами.

Это конкретные незавершённые части интеграции исходного приложения. Они не закрываются одной заменой файлов UI.
