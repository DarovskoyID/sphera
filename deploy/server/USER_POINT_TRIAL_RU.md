# Установка обычного поинта: проверенный пользовательский сценарий

Для тестовой сети из семи VPS на чистой Ubuntu 22.04 с уже доступным git:

```bash
git clone --depth 1 --branch codex/wan-prepare-20261118 https://github.com/DarovskoyID/sphera.git /root/sphere
bash /root/sphere/scripts/linux/install-point.sh
```

Обе команды выполняются от root. Вторая команда сама проверяет подписанный публичный профиль, получает Python и пакеты с GitHub, создаёт отдельное окружение и локальный ключ, получает лицензию/сертификат поинта и включает службы. Индивидуальные IP, genesis, ключи и роли пользователь не вводит. Исходники и артефакты Sphere загружаются с GitHub; системные bootstrap-зависимости устанавливаются через Ubuntu APT.

Фактический чистый запуск на 38.244.178.206: git clone — код 0, 2,2 с; install-point.sh — код 0, 152,1 с. После двух команд внешний HTTPS-ready вернул 200 и ожидаемый ключ; в подписанном реестре присутствовала новая седьмая точка. Роль — point. Валидатор не устанавливался. Ключ создан на сервере и остаётся там, права 0600. Включён автоматический запуск основной службы и таймер обслуживания.

Третья SSH-команда использовалась оператором исключительно для итогового квалификационного задания: исходящая передача и повторное чтение. Она не является шагом установки пользователя. Полный отчёт и точный вывод находятся в рабочем артефакте `output/kazakhstan-user-install-20261119/`.

Этот профиль относится к подписанному испытательному выпуску `wan-trial-20261118`, а не к опубликованной production-сети. Веб-интерфейс здесь не разворачивается. Сборщики измерений и начальные валидаторы уже действующей сети — отдельные операторские роли; установка обычного пользователя их настройки не требует. Резервного bootstrap-входа пока нет.
