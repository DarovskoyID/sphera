# Веб-вход на поинтах

Развёрнут на семи существующих VPS: https://38.180.140.174, https://38.180.140.161, https://38.180.95.155, https://38.180.2.229, https://149.33.34.85, https://38.180.162.39, https://38.244.178.206.

Доступны создание сетевой учётной записи, вход подписанным доказательством, проверка/завершение сессии, сохранение зашифрованного ключа и выбор поинта. На другом поинте пользователь открывает этот файл и вводит пароль. Пароль и закрытый ключ обрабатываются в браузере. В хранилище браузера сохраняется зашифрованный vault; токен сессии остаётся в оперативной памяти.

Это веб-вход в mesh, а не развёртывание прежнего Django/JWT мессенджера. Чаты, звонки и полный интерфейс приложений потребуют отдельного подключения прикладного API.

Одинаковые публичные файлы раздаются Caddy 2.11.9 с публичными сертификатами IP. Документация TLS/ACME: https://caddyserver.com/docs/caddyfile/directives/tls . Сертификаты выпускаются и обслуживаются на каждом VPS, домен для текущего стенда не нужен. Caddy и loopback-адаптер работают от отдельного sphere-web; приватный ключ поинта им не передаётся. Адаптер слушает 127.0.0.1:9080, проверяет consensus snapshots исходным Go verifier и публикует только валидные подписанные начальные записи аккаунтов. Авторизация проксируется в собственный поинт на 8443 с проверкой его TLS через сетевой CA. Административный API Caddy отключён.

Исходники клиента в web-entry/. Для самостоятельной сборки: npm install, затем npm run build в этой папке. На VPS устанавливаются предсобранный архив и подписанный установщик с GitHub; Node/npm на VPS не нужны. Подписанный пакет текущего стенда содержит публичные привязки этих семи узлов. HTTP 80 используется для ACME/перенаправления, HTTPS 443 — для веб-входа.

Проверено: одинаковый JS bundle на семи точках, TLS цепочки без исключений, соответствие ключа каждого входа, одна тестовая учётная запись на всех семи поинтах, подписи login/session/logout и отказ токена после logout, отказ неподписанной регистрации. В браузере проверены экраны входа и создания аккаунта; криптографические сценарии проверены тем же SDK через реальные публичные API. Полный SSH-журнал и результаты — output/point-web-20261119/ рабочего пространства.

Первый пилот выявил влияние umask на права каталогов; права исправлены до общей установки. Австралийский запуск сначала ошибочно принял netlink-сокет за веб-порт; фильтр уточнён до TCP. Эти попытки сохраняются в журнале.
