# WAN trial roles and bounded HTTPS client policy

This is a six-VPS same-owner simulation. Four local assessment daemons use the keys already authorized by genesis, one key per validator host. Keys are read only locally, never uploaded or copied to an assessor key file. The observation identities are separate licensed identities. These roles do not demonstrate independent ownership.

`server_wan_managed.py` provisions assessment and placement-controller services from the publisher-signed trial job archive. The controller stages the first three resource grants until the initial batch is confirmed, then resumes grants for the complete signed inventory. Point configuration and its supervisor policy remain unchanged.

An optional signed activation-profile field `managed_roles` contains exactly `failure_domains` (node ID to operator-pinned simulation site) and `capacity_policy` (bytes_per_slot, transport_bytes_per_second_per_slot, disk_bytes_per_second_per_slot, reserve_bytes). When present, the third activation command provisions its local assessment role and the bootstrap host discovers all four licensed assessment endpoints before starting the controller. The activation archive must include `server_wan_managed.py` and `server_trial_seed.py`. This combined fresh-install path still needs a complete clean deployment test; live trial provisioning used additional SSH commands and must not be presented as a three-command installation of all roles.

HTTPS clients accept `ConfiguredHttpsTransport(peers, context=context, timeout_seconds=10)` and the same parameter on `DiscoveredHttpsTransport`. The integer limit must be 1..10 seconds, default 3. TLS verification, pinned routes, signed envelopes, replay checks, response limits and request binding remain enabled. Existing installed point daemons retain their published code and default policy; the signed WAN workload job can load its two updated client modules directly from its verified archive. This is not a deployment of a new stable server release.

Qualification jobs bound the dataset, retry count, service pauses and firewall rules. Partition recovery is scheduled independently before applying a temporary chain; only port 26656 and explicitly pinned other validators are targeted. The repair exercise deletes one explicitly pinned 1052-byte test ciphertext, verifies absence and observes its digest-matching reappearance without issuing a replacement put.

Linux checks: `python -B scripts/test-mesh-public-transport.py` and `python -B scripts/test-wan-trial-job.py`. Live receipts remain separate from source and contain no private keys or credentials. The six-server trial does not close the seven-server campaign; Kazakhstan is pending. Bootstrap restart recovery does not provide an availability failover endpoint.
