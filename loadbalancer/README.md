# Load Balancer (nginx) для ws-gateway

Балансировщик нагрузки перед WebSocket-шлюзами (`ws-gateway`, порт 8001).
Внутри контейнера слушает порт **8001**, наружу проброшен на `127.0.0.1:8081`
и распределяет соединения между нодами из пула.

Цепочка трафика в проде:
`клиент (wss://host:8001)` → `внешний nginx (TLS)` → `балансировщик (127.0.0.1:8081)`
→ `ноды ws-gateway (servers.conf)`.

## Как добавить/убрать сервер

1. Откройте **`servers.conf`** — это единственный файл со списком IP.
2. Добавьте строку:
   ```nginx
   server 10.0.0.12:8001 max_fails=3 fail_timeout=10s;
   ```
3. Примените без простоя:
   ```bash
   docker compose exec loadbalancer nginx -s reload
   ```
   (или `docker compose restart loadbalancer`)

## Файлы

| Файл          | Назначение                                              |
|---------------|---------------------------------------------------------|
| `servers.conf`| Список IP серверов — **редактировать только его**       |
| `nginx.conf`  | Конфиг балансировщика (таймауты, WS-upgrade, алгоритм)   |
| `Dockerfile`  | Образ на базе `nginx:alpine`                             |

## Алгоритм балансировки

По умолчанию `ip_hash` — клиент всегда попадает на ту же ноду (sticky session,
важно для WebSocket). Так как фан-аут сообщений между нодами идёт через Redis
pub/sub, можно переключить на `least_conn;` в `nginx.conf` для более ровной
нагрузки — клиенты всё равно получат все сообщения.

## Проверка

```bash
curl http://localhost:8081/lb-health      # здоровье самого балансировщика
docker compose logs -f loadbalancer       # логи проксирования с $upstream_addr
```

Фронтенд подключается к WebSocket по адресу `wss://<host>:8001` (порт `WS_PORT`
в `src/config/network.ts`), который внешний nginx терминирует и проксирует на
балансировщик.
