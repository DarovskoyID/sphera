## Исправление каталога модулей — 20 ноября 2026

В распределённом URLconf отсутствовали `/api/modules/` и `/api/modules/public/`.
Теперь подключены существующие обработчики каталога реально установленных модулей.
Обычный пользователь не получает полномочий установки: `can_manage=false`.
Загрузка модулей из Git в immutable release-каталог отключена; полноценный
операторский runtime установки модулей остаётся отдельной незавершённой задачей.

`/api/auth/me/` явно сообщает возможности поинта. При распределённом режиме
первоначальная загрузка UI не вызывает отсутствующие персональные API контактов,
блокировок, эмодзи и настроек. Это не реализация этих API и не обещание готовых чатов.
Списки предыдущего сервера очищаются при таком переключении.

Повторный вход также исправлен: локальная запись устройства выбирается по
подписанному device ID, а не по IP, который может совпадать у нескольких устройств.
Криптографические проверки и ограничения сессии сохранены. Реальный JWT-тест
с несколькими устройствами на одном IP прошёл. В браузере повторный вход в
ранее созданный аккаунт и перезагрузка прошли без прежнего окна ошибки.

Проверены все семь поинтов: авторизованный каталог — 200, анонимный — 401,
публичный каталог — 200. После проверки выполнен выход из тестового аккаунта.

`modules-catalog-fixed.png` и полный `SSH_REPORT_RU.md` в локальной папке
`output/distributed-registration-20261119`.
