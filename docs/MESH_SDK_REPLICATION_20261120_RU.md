# Распределённые ключи и сообщения — 20 ноября 2026

Прикладной модуль работает отдельно на каждом из семи поинтов. Общей базы SQL и Redis нет. Каждый поинт хранит проверенные SDK-документы и шифрованные операции в собственном журнале SQLite. Запись подтверждается после ответов более чем двух третей прикладных реплик; в текущем составе это пять из семи. Чтение сверяет копии и восстанавливает незавершённую репликацию перед проекцией в локальную базу. Подтверждения получения ключевых пакетов сохраняются как постоянные отметки, чтобы отставшая копия не вернула пакет повторно.

Служебные идентичности начальных валидаторов не считаются прикладными репликами. Совпадения IP недостаточно: поинт отвечает на свежий запрос подписью своего допущенного ключа. Найденные соответствия сохраняются, поэтому временно недоступный прикладной поинт не исчезает из числа требуемых подтверждений. В этом испытательном составе проверены семь прикладных идентичностей вместо одиннадцати общих транспортных.

Одноразовые ключи выдаёт только журнал консенсуса. Добавлены резервные ключи SDK: обычные одноразовые выдаются первыми, резервные допускают повторное использование, а замена окончательно выводит предыдущий резервный ключ из выдачи. Повторная загрузка и переименование не возвращают использованный одноразовый или заменённый резервный ключ.

После входа SDK публикует публичные ключи устройства до первого открытия чата. Файл ключей не нужно импортировать заново при обычном входе. В памяти остаются неэкспортируемые возможности подписи и вывода ключей; пароль и открытые корни не сохраняются. После перезагрузки страницы зашифрованные локальные ключи можно открыть паролем.

Шифрованное сообщение подписывается SDK, реплицируется и только затем восстанавливается в локальном SQL. Ключ локального шифрования SQL у каждого поинта свой. Повтор операции не создаёт второе сообщение, подмена того же идентификатора другим содержимым отклоняется. Истечение короткого разрешения во время SDK-операции требует свежего подтверждения того же состава; изменение эпохи или состава блокирует выдачу результата.

## Проверено

- Полный набор тестов Go-консенсуса; одинаковые результаты Go и Python для одноразовых и резервных ключей.
- Семь независимых баз, подписи устройств и поинтов, отказ без кворума, отставшая копия, постоянные отметки получения, отделение четырёх служебных идентичностей от семи прикладных.
- Настоящий WASM SDK: начальная публикация ключей, выдача через журнал, обмен шифрованными сообщениями и расшифровка в обе стороны.
- Реальные миграции Django, локальная проекция, повторная обработка и отказ при подмене шифропакета.
- Реальные Казахстан и Великобритания: оба участника вошли, открыли SDK с защитой профиля, отправили и расшифровали сообщения в обе стороны. В ответах серверов нет открытого текста. Доказательство: output/sdk-replica-20261120/wan-messages-result.json.
- Сборка Vite и проверка типов приложения с отключёнными проверками неиспользуемых объявлений. Отдельные прежние ошибки типов refs и недостающие строки записи мультимедиа в переводах исправлены.
