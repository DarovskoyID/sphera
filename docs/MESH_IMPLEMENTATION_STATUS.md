# Mesh: состояние реализации

19 октября 2026 года. Требования: [архитектура](MESH_NETWORK_ARCHITECTURE_RU.md).

## Реализован первый слой

- Отдельный Python-пакет sfera_mesh, не подменяющий текущий сервер mesh-сетью.
- Двунаправленные блоки шифротекста, защита от повторных ID в локальной модели, курсоры последних 100 сообщений.
- Дерево Merkle и проверка доказательств с контролем позиции, размера дерева, изменения содержимого и лишних элементов доказательства.
- Локальное устойчивое SQLite-хранилище блоков и отдельный индекс: двунаправленные связи, контрольные точки, индекс cluster → затронутые диапазоны, проверка шифротекста при чтении, сохранение метаданных после потери блока.
- Подбор троек по количеству оплаченных модулей, затем совпадению наборов; обязательная проверка разных зон отказа, ресурсов и отметки проверенной лицензии.
- Выбор временного соседа с ограничением двух кластеров. При одинаковой совместимости свободный сервер предпочтительнее уже занятого.
- Чистая функция доступа по разрешениям выбранного entry point. Действующие серверные проверки лицензий остаются в sfera_modules и не заменены доверенными флагами клиента.
- Linux install.sh с выбором corporate/personal/mesh, сохранением standalone-режима и запретом молчаливой смены. Mesh отклоняется до изменения файлов, пока нет сетевого runtime.
- Режим deployment.env подключается к создаваемым systemd-сервисам; прежние установки без настройки остаются personal, вне mesh.
- Проверки алгоритмов и изоляции установщика подключены к CI.

## Границы первого слоя

Это не готовая mesh-сеть. Тест семи кандидатов проверяет подбор, а не семь сетевых серверов. Хранилище не подтверждает распределённую запись. Узлы дерева сохраняются в SQLite и обновляются по пути добавленного блока; доказательство запрашивается по уровням без полного обхода истории. Полная функция leaves нужна только для диагностического сравнения с эталоном в тестах. Шифротекст поступает готовым: шифрование и проверка E2EE-происхождения ещё не интегрированы. Флаг grant_verified — внутренний вход алгоритма, не HTTP API и не замена проверки подписи коммерческого сервиса.

## Следующие обязательные части

1. Подписанные сетевые идентичности, admission и проверяемые подтверждения лицензий от коммерческого API.
2. Репликация и консенсус с durable quorum, learner-процедурой, сменой состава и fencing старых участников. Выбранная библиотека должна иметь проверенный протокол; локальная модель его не заменяет.
3. Распределённый каталог аккаунтов и размещения, внешние контрольные точки и индекс доступности.
4. Клиентское хранилище ключей Argon2id, протокол входа, E2EE диалогов/групп, восстановление и отзыв устройств.
5. Интеграция истории с действующим API и UI, ручной выбор entry point и объяснение недоступных модулей.
6. Сетевой стенд на семи изолированных узлах с отказами, затем реальный месячный стенд.
7. Включение рабочего mesh-режима установщика только после этих проверок.

Данные текущего сервера не мигрированы, шифрование не переключено, существующие аккаунты в mesh не опубликованы.


Уточнение доверия: участие операторов открыто для всех. Raft/обычное большинство тройки не выбраны как защита от злонамеренных серверов. Пользователь согласовал тройки хранения и роли валидаторов на тех же серверах. Комитет требует минимум четырёх node_id из разных троек; Sybil-защита не определена. Пока разрабатываются независимые от этого решения хранилище, индексы и политики размещения.


Дополнительно реализована проверка подписанных контрольных точек Ed25519: идентичность сети и комитета, версия, предыдущий хеш, порог более 2/3, отклонение повторных подписантов и изменённых данных. Локальный SQLite-журнал запрещает повторную подпись другого содержания на той же высоте даже после перезапуска. Это проверка сертификатов и защита от двойной подписи, а не готовый BFT-консенсус: раунды, блокировки, смена комитета, защита от отката доверенной конфигурации и Sybil остаются обязательными. Сертификат не может сам назначить собственный доверенный набор подписантов.
